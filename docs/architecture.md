# Architecture Note: assistant_core

## 1. Module Table

| Module | Responsibility |
| :--- | :--- |
| `config.py` | Read settings from the environment and validate them |
| `errors.py` | Define domain-specific named exceptions. |
| `models.py` | Define public contract models: `Message`, `Response`, `Intent`, `Source`. |
| `router.py` | Determine an `Intent` from query text using rule-based logic. |
| `knowledge.py` | Load and search office directory (`offices.csv`) and student handbook (`handbook.json`). |
| `tools.py` | Provide deterministic tuition fee calculations without I/O or global state. |
| `responder.py` | Generate responses behind a single interface (`Responder` protocol, template, stub LLM). |
| `service.py` | Implement `AssistantService.handle(Message) -> Response` as the single entry point. |
| `logging_setup.py` | Configure structured JSON logging. |
| `__main__.py` | Provide the command-line interface (CLI) entry point. |

---

## 2. The Service Interface

* AssistantService.handle(msg: Message) -> Response
* Message: text (1–2000 chars), session_id
* Response: answer, intent, sources[], degraded (True if a fallback was used)
* Errors: invalid input -> ValidationError; startup -> ConfigError / DataError;
provider failures never reach the caller (fallback instead)


---

## 3. Key Architectural Decisions

* **Deterministic Tools for Financial Calculations:**
  * **Decision:** Tuition fees are calculated using pure functions in `tools.py` rather than generated by an LLM.
  * **Reason:** Guarantees exact, testable, and reproducible results without risks of non-deterministic arithmetic errors or hallucinations from the language model.

* **Adapter Pattern for Response Generation (`Responder` Protocol):**
  * **Decision:** The LLM provider sits behind a `Responder` interface using Python's `Protocol`.
  * **Reason:** Allows injecting `StubLLMResponder` for local development, unit tests, and CI/CD runs offline without requiring active API keys. Real AI providers can be integrated later without modifying `AssistantService`.

* **Externalized Configuration (Twelve-Factor App Factor III):**
  * **Decision:** All application parameters are loaded from environment variables using `python-dotenv` and Pydantic validation (`config.py`), with `.env.example` documenting all fields.
  * **Reason:** Strictly separates configuration from code, preventing credential leaks (API keys use `repr=False`) in version control while making deployment simple across dev, test, and production environments.
